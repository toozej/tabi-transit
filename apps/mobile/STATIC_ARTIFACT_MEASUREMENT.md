# Static artifact decision evidence (D-013)

Command (run from the repository root):

```sh
node apps/mobile/scripts/measure-static-artifacts.mjs
```

The script deterministically generates 4,000 stops, 180 routes, 25,000 trips,
and 180,000 stop-times. It reports compact JSON size and a normalized
SQLite-row **proxy** representation, plus Node.js serialization/parse/filter
proxies. It performs no network, device, Expo, SQLite-native, or location work.

## Result recorded on this workstation

The exact values are intentionally regenerated by the command rather than
treated as portable performance claims. The initial run on this workstation
reported JSON `17,898,363` bytes (`1,975,299` gzip bytes) and normalized-row
proxy `17,898,336` bytes (`1,975,267` gzip bytes). It measured JSON parse at
about `113 ms` and a linear stop-time lookup at about `1.9 ms`; those values
are Node.js-only proxies, not device performance. Equivalent serialized sizes
are expected because the normalized proxy is represented as JSON tables; the
linear lookup still demonstrates why an eventual SQLite implementation needs
an index rather than a scan.

Interpretation:

- JSON remains the Phase 2 default for versioned, download-only static
  artifacts because it is simple to validate, hash, replace atomically, and
  expose in fixture/degraded mode.
- A normalized SQLite artifact should be selected only after physical-device
  measurements prove its indexed query/startup/update advantage and its native
  migration behavior. The proxy does not establish that evidence.
- Any SQLite follow-up must benchmark indexed `stop_id` lookup, artifact
  download/update atomicity, and warm/cold startup on supported iOS and Android
  development builds. Until then, preserve the JSON artifact as the ADR's
  default and do not claim offline schedules were device-validated.

Privacy: this fixture has synthetic IDs/names and contains no rider location,
search text, credentials, or provider payloads.
